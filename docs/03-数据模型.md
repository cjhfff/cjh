# 03 数据模型

Alma 的数据库里实际有 **90 张表**，其中 40 张是用 drizzle 声明的，其余的是原生 SQL 建的（FTS5 全文索引、sqlite-vec 向量表、活动记录、团队、时间线索等）。完整清单见 `raw/tables.txt`。

下面只讲 cjh 用得上的部分。

---

## 1. 核心表（MVP 必需）

### providers：模型来源

| 字段 | 用途 |
|---|---|
| id | 主键，也是模型字符串 `providerId:modelId` 的前半段 |
| name | 显示名 |
| type | 共 18 种：openai, anthropic, google, aihubmix, openrouter, deepseek, copilot, azure, moonshot, custom, **acp**, claude-subscription, zai-coding-plan, kimi-coding-plan, opencode-go, cloudflare-ai-gateway, ollama, volcengine |
| api_key / base_url / api_version | 连接参数 |
| api_format | `openai-chat` / `openai-responses` / `anthropic`。**custom 类型靠这个字段决定按哪种协议请求**，接中转站全靠它 |
| is_response_api / use_max_completion_tokens | 兼容开关：有的中转只支持 Responses API，有的模型要求用 `max_completion_tokens` 代替 `max_tokens` |
| custom_headers | 额外的请求头 |
| models (json) | 已经启用的模型及其能力（vision、reasoning、contextWindow、maxOutputTokens、streaming、functionCalling） |
| available_models (json) | 从远端拉到的全部模型，供用户勾选 |
| acp_command / acp_args | ACP agent 的启动命令 |
| acp_mcp_server_ids (json) | 要透传给 agent 的 MCP server |
| acp_auth_method_id | ACP 认证方式 |
| acp_api_provider_id | 让 ACP agent 借用另一个 provider 的 key 和 base URL |
| acp_model_mapping (json) | 模型名映射 |
| image_generation_mode | 图片生成走同步还是异步 |
| enabled / icon / created_at / updated_at | |

### chat_threads：线程

| 字段 | 用途 |
|---|---|
| id, title | |
| model | 这个线程用的模型（`providerId:modelId`） |
| reasoning_effort, fast_mode | 每个线程单独设置 |
| tools (json), skill_ids (json) | 这个线程启用了哪些工具和技能 |
| workspace_id | 绑定的工作区 |
| parent_thread_id | 分支来源 |
| is_generating | 是否正在生成（重启后要清理掉） |
| is_favorited, is_favorite_pinned, favorite_pinned_order, sidebar_pin_slot | 收藏和置顶 |
| is_incognito | 无痕 |
| metadata (json) | 其他杂项，包括当前活跃分支等 |

### chat_messages：消息（树形结构）

| 字段 | 用途 |
|---|---|
| id, thread_id（级联删除） | |
| parent_id | 父消息，用来构成消息树 |
| slot_id | 同一个位置上的多个版本共用一个 slot，切换版本就是在同一个 slot 里换 |
| depth | 树的深度 |
| parent_tool_call_id | 子 agent 的消息挂在哪次工具调用下面 |
| message (json) | **整条 AI SDK UIMessage**：`{id, role, parts:[{type:"text"}, {type:"reasoning"}, {type:"tool-xxx"}, {type:"file"}…]}` |
| metadata (json) | 用到的模型、token、耗时等 |
| timestamp, created_at, updated_at | |

### app_settings：设置

只有**一行**，`settings_data` 字段是一个 JSON 大对象。观察到的顶层分组（只读了键名）：

```
general     { theme, language }
ui          { density }
chat        { defaultModel, defaultToolSelection }
toolModel   { model }                    ← 做杂活的模型
feishu      { enabled, defaultModel }
weixin      { enabled, defaultModel }
mobileRelay { enabled, serverUrl, connectCode, e2eEncryption }
activityRecorder { … 十几个截屏和 OCR 参数 }
onboarding  { dismissed }
remoteLaunch { lastWindow }
```

一行 JSON 的做法改起来很灵活，但不能单独查某个设置项。**cjh 也可以这么做**，只是要写 schema 校验（比如 zod），并且每次修改后广播 `settings_updated` 事件。

### usage_records：用量

按消息记录：message_id、thread_id、model、provider_id、date，以及 input、output、cached_input、cache_write_input、reasoning、total 这几种 token。标题、记忆整理这类杂活的用量单独记在 **aux_usage_records** 里，用 `purpose` 字段区分用途。

## 2. P1 用到的表

| 表 | 关键字段 |
|---|---|
| mcp_servers | registry_id, name, config (json), enabled, status, last_error |

| thread_labels | name, color, sort_order |
| secrets | name（主键），encrypted_value, note, env（是否作为环境变量注入） |

| messages_fts | FTS5 全文索引，对 chat_messages 的文本做索引 |

## 3. cjh MVP 建议的表结构

只建这 7 张，其他的等做到对应功能时再加：

```
providers        id, name, type[openai|anthropic|openai-compatible|acp], api_format,
                 api_key(加密), base_url, custom_headers(json), models(json), available_models(json),
                 acp_command, acp_args(json), acp_env(json), enabled, created_at, updated_at

threads          id, title, model, reasoning_effort, active_leaf_id, workspace_path,
                 is_pinned, metadata(json), created_at, updated_at

messages         id, thread_id, parent_id, slot_id, role, message(json: UIMessage),
                 metadata(json), created_at

settings         id=1, data(json)

usage_records    id, message_id, thread_id, provider_id, model, input_tokens, output_tokens,
                 cached_input_tokens, reasoning_tokens, total_tokens, created_at

mcp_servers      id, name, transport[stdio|http|sse], config(json), enabled, status, last_error

schema_migrations
```

和 Alma 不同的几个地方：

- **providers 加了 `acp_env`**：直接在 provider 上配环境变量，比如 `CLAUDE_CODE_EXECUTABLE`、`ANTHROPIC_BASE_URL`。Alma 没有这个字段，所以今天只能去改全局环境变量，再写一个包装脚本。
- **threads 用 `active_leaf_id` 记录当前分支**，不塞进 metadata。
- **api_key 要加密存储**，用 Windows DPAPI 或 Electron 的 safeStorage。Alma 的 `providers.api_key` 是一个普通文本列，表结构上看不出有加密层（我没去读里面的值，所以不确定它在应用层有没有加密）。

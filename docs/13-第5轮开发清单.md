# 第 5 轮开发清单：终端工作区（herdr 模式）

目标：让 cjh 像 Alma 一样，**监控和驱动用户在终端里跑的编码 agent**（agy / Antigravity、Codex、Claude Code、pi……），在 cjh 和飞书里看状态、收通知、回复、审批、派任务。

## 0. 背景（已确认的事实）

- Alma 的「herdr」不是自己写的终端，而是 **Herdr Core（`hc`）的客户端**。Herdr Core 是独立程序，用户机器上已安装并在运行：
  - 可执行文件：`C:\Users\d\AppData\Local\Programs\herdr-core\herdr-core.exe`（版本 `hc 0.1.21`）
  - 数据目录：`%LOCALAPPDATA%\herdr-core\default\`（`core.json`、`terminals.json`）
  - 设置：`~/.config/herdr-core/config.toml`
- 完整 API（OpenRPC / JSON Schema）：[raw/herdr-schema.json](raw/herdr-schema.json)；CLI 手册：[raw/herdr-skill.md](raw/herdr-skill.md)。**实现前必须先读这两个文件**，方法名、参数、错误码以它们为准，不要凭想象。
- 关键方法：`hello`、`server.status`、`terminal.list/get/run/read/send/keys/interrupt/wait/kill/rm/label/put/attach`、`events.subscribe`、`templates.list`、`machine.list`、`rpc.discover`。
- 传输：`herdr-core.exe connect` 在 stdin/stdout 上提供同一套 API（`hello` 带 `framed: true` 才切到带帧模式，用于 `terminal.attach` 原始流）。也可以每次调用 `herdr-core.exe <cmd> --json`。**优先用一个长连的 `connect` 子进程做 JSON-RPC + 订阅事件**，CLI 方式只作兜底。具体行分隔还是什么格式，先用 `hello` 实测确认，写进实现注释。
- 状态模型：terminal 有 `state`（live/finished）、`turn`、`agent`、`cwd`、`labels`，以及 `status`（OSC 7501 记录）：`state` ∈ idle / working / done / blocked / error，blocked 时 `kind` ∈ permission / question / auth，另有 `msg`、`title`、`progress`。herdr 已能识别 `antigravity`（agy）、`codex`、`claude`。
- `agy` 自带 ACP 服务：`agy acp`（stdio）。

## 1. 需求

### R0　agy 作为 ACP 预设（小）
- providers 的 ACP 预设里新增 `antigravity`：命令 `agy acp`，Windows 默认探测 `C:\Users\<user>\.gemini\bin\agy.exe`，可在设置里改路径。沿用现有 fail-closed 权限模式设置流程（若 agy 不支持 set_mode，按现有逻辑处理，不能静默变成 bypass）。
- 单测覆盖预设解析。

### R1　HerdrClient（server）
- 新模块 `src/server/herdr/`：
  - 定位 `herdr-core.exe`：设置项 `herdr.execPath` → 默认安装路径 → PATH 里的 `hc`/`herdr-core`。
  - 长连 `connect` 子进程，JSON-RPC 请求/响应按 id 匹配，超时、退出自动重连（指数退避，上限 30s），daemon 退出时清理。
  - `events.subscribe` 订阅，把 terminal 的 created / status / turn / title / finished / removed 等变化转成 ws 事件 `herdr_terminal_*` 广播；保持一份内存快照。
  - 不可用（未安装 / 启动失败）时不报 500，`/api/herdr/status` 返回 `{available:false, reason}`。不负责安装 herdr。
- HTTP 路由 `/api/herdr/*`（全部走现有 Bearer 鉴权，zod 校验）：
  - `GET status`、`GET terminals?all=`、`GET terminals/:t`、`GET terminals/:t/screen?lines=`
  - `POST terminals`（run：`agent` ∈ agy/codex/claude/pi/shell/自定义命令，`cwd`、`name`、`task`、`labels`；默认 `--bg` 语义，打上 `cjh=1` 标签）
  - `POST terminals/:t/send`（text，`force` 默认 false）、`POST terminals/:t/keys`、`POST terminals/:t/interrupt`、`POST terminals/:t/answer`（blocked 时按选项号/文本作答，内部转成 keys）、`DELETE terminals/:t`（kill，需二次确认参数）、`POST terminals/:t/rm`、`POST terminals/:t/label`、`POST terminals/:t/put`（上传图片/文件）
  - `GET machines`、`GET templates`
  - 「工作区」= 按 `cwd` 分组，前端或 `GET workspaces` 聚合即可，不新建表。
- agent 启动命令映射写在一处（例如 agy → `agy`，codex → `codex`，claude → `claude`），可在设置覆盖。

### R2　终端视图（renderer）
- 左侧导航新增「终端」页：
  - 列表按工作区（cwd）分组，每行显示 地址/名字、agent 图标、状态徽标（working 转圈、blocked 红、done 绿、idle 灰、error 橙）、`msg`/`title`、turn、静音开关。
  - 右侧详情：屏幕内容（`terminal.read`，状态/turn 变化时和 working 期间每 1.5s 刷新；用 xterm.js 只读渲染或等宽 `<pre>`，ANSI 颜色可选）。
  - 底部输入框：发送（send），快捷键按钮（Enter / Esc / ↑ / ↓ / Ctrl+C / 中断）。blocked 时在顶部显示提示条：`kind`、`msg`、屏幕上的选项，点选项号即作答。
  - 「新建终端」对话框：选 agent、选目录（复用工作区目录选择）、名字、首条任务。
  - herdr 不可用时显示原因和 herdr 安装说明，不崩。
- P1（本轮可选，做完 P0 再做）：xterm.js 实时 attach（framed 流），可直接键入。

### R3　通知、静音与飞书
- 状态迁移触发通知：`working → blocked`（需要你）、`working → done/idle`（跑完了）、`→ error`、程序 finished。
  - 桌面通知（Electron Notification），点击跳到该终端。
  - 若飞书已配置且有默认通知会话：发卡片（终端名、agent、cwd、状态、屏幕最后 ~20 行）。blocked 卡片带选项按钮（作答）；所有卡片可「回复」→ 文本 send 到该终端。
  - 每个终端可静音（存 settings 或 herdr label `cjh.mute=1`），静音后不推送。
  - 去抖：同一终端 5s 内同类迁移只推一次；cjh 自己发送引起的 working 不算新任务。
- 飞书侧支持文本指令：`/t ls`、`/t <t> <文本>`、`/t <t> 1`（作答）。

### R4　让 cjh 的模型能派活（follow）
- 内置工具（走现有 PermissionGate；`run`/`send`/`keys`/`answer`/`kill` 需审批，`list`/`read`/`wait` 不需要）：`herdr_list`、`herdr_read`、`herdr_run`、`herdr_send`、`herdr_answer`、`herdr_wait`（带超时上限）。
- follow：`herdr_run`/`herdr_send` 可带 `follow:true`。被 follow 的终端每次从 working 停下，把「最后回复 + 屏幕上等待的东西」作为一条消息注入发起它的 cjh 线程并触发一轮生成，让模型决定下一步（继续 send、作答，或告诉用户完成）。线程里可取消 follow；同一终端只能被一个线程 follow。
- 新技能 `resources/skills/herdr/SKILL.md`：教模型什么时候把编码任务交给终端 agent、怎么写自包含的任务、怎么跟进。

### R5　CLI
- `cjh term ls`、`cjh term read <t>`、`cjh term run <agent> [--cwd] [--name] [task]`、`cjh term send <t> <text>`、`cjh term answer <t> <n|--text>`、`cjh term follow <t> --thread <id>`，走 daemon 的 HTTP API。

- 不动已有功能的行为；typecheck、`npm test`、`npm run build` 必须全部通过，原有 41 个用例不能挂。
- 中文 UI 文案进 `src/shared/i18n/zh-CN.ts`。
- 完成后在本文末尾追加「完成说明」：做了什么、改了哪些文件、怎么测的、没做的和原因。

## 5. 小昌复验（2026-11-20）

### 5.1 发现并修复的问题

- **P0：连接真实 herdr 时无限递归，整个终端功能不可用。** `HerdrClient.enrichTerminal → getFollower → HerdrFollowManager.resolveAddress → HerdrClient.getCachedTerminal → enrichTerminal`。只要本机有终端，连接时就会报 `Maximum call stack size exceeded`，`/api/herdr/status` 返回 `available:false`。单测用 mock 的 follow manager，所以没测出来；`scripts/herdr-smoke.mjs` 是直接调 `hc`，没经过 `HerdrClient`，所以冒烟也没发现。
  - 修复：`client.ts` 抽出不做 enrich 的 `findRawTerminal`，新增 `resolveCachedAddress`；`follow.ts` 的 `resolveAddress` 改用它（`HerdrClientLike` 增加可选方法）。
  - 回归单测：`round5-r0-r1.test.ts`「does not recurse when a real HerdrFollowManager enriches a non-empty snapshot」，用真实 `HerdrFollowManager` + 两个已有终端；去掉修复时该用例必挂（已验证）。

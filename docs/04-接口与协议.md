# 04 接口与协议

## 1. 总体约定（Alma 的做法）

- 只监听 `127.0.0.1`，端口每次启动随机分配。前端由壳在启动时告知端口。
- **增删改查走 HTTP（REST）**，**生成和实时状态走 WebSocket**。
- 服务端发生的任何变化都会通过 WS 广播事件，所以多个窗口和客户端之间天然同步。
- 一共 827 条路由，完整清单见 `raw/routes.txt`。

cjh 照这个模式做就好。额外建议：

- 启动时生成一个随机 token，前端和 `cjh` CLI 都要带上它。只绑定 127.0.0.1 不够，本机其他程序也能访问这个端口，Alma 的 `/api/*` 对我直接发的请求就没有做任何校验。

## 3. WebSocket 协议

### 客户端发给服务端：只有 3 种

**`generate_response`**：发起一轮生成

```jsonc
{
  "type": "generate_response",
  "data": {
    "threadId": "…",
    "userMessage": { "role": "user", "parts": [ {"type":"text","text":"…"}, {"type":"file","url":"data:…","mediaType":"image/png"} ] },
    "model": "providerId:modelId",   // 可选，不填就用线程上的模型，再不行用默认模型
    "reasoningEffort": "high",       // 可选
    "fastMode": false,               // 可选
    "tools": ["…"],                  // 可选，这一轮启用哪些工具
    "enabledMCPServerIds": ["…"],    // 可选
    "noTools": false,
    "retryOfMessageId": "…",         // 重试某条 assistant 消息（此时 userMessage 为 null）
    "replaceMessageId": "…",         // 编辑某条用户消息后重发
    "regenerate": true,
    "ephemeralContext": "…",         // 只在这一轮注入、不落库的上下文（渠道桥接用它带群聊背景）
    "ephemeralModel": "…",           // 只在这一轮临时换模型
    "source": "telegram | telegram-group | system-commitment-followup | background-resume | …",
    "userMessageMetadata": { }
  }
}
```

**`steer_generation`**：字段和上面一样。如果线程正在生成，就把这条消息并入当前这一轮；没在生成，就退化成普通的一轮。

**`stop_generation`**：`{threadId}`

### 服务端推给客户端：事件

都是 `{type, data, timestamp}` 格式。

| 类别 | 事件 |
|---|---|
| 生成过程 | `thread_generating`（开始/结束）、`message_start`、`message_delta`、`message_stop`、`tool_use`、`tool_input_append`、`tool_output_streaming`、`tool_output_set`、`tool_result`、`generation_completed`、`generation_error` |
| 消息变化 | `message_added`、`message_updated`、`message_deleted` |
| 线程 | `thread_created`、`thread_updated`、`thread_deleted`、`title_generating`、`title_generated` |
| 上下文 | `context_usage_update`、`context_compaction_started`、`context_compacted` |
| 配置 | `settings_updated`、`provider_updated`、`provider_deleted`、`skills_refreshed`、`labels_updated` |
| 工作区 | `workspace_created`、`workspace_updated`、`workspace_deleted` |
| 终端 | `terminal_created`、`terminal_closed`、`terminal_resize` |
| 后台进度 | `memory_retrieval_progress`、`memory-rebuild-progress`、`local-embedding-progress`、`tool_analysis_progress`、`skill_analysis_progress` |
| 出错 | `{type:"error", data:{error}}` |

### 设计要点

1. **流式事件和落库事件分开发**：`message_delta` 只用来实时显示，生成结束后会再发一次完整的 `message_updated`。客户端最终以 `message_updated` 为准，丢了几个 delta 也不影响最终结果。
2. **重连后补状态**：客户端连上后先拉一次线程和消息，再根据 `thread_generating` 判断要不要接着显示生成中的状态。
3. **线程级别的锁**：同一线程同时只能有一轮生成。新的请求要么 steer 进当前这一轮，要么 supersede（替换掉旧的），要么 fork 成新的一轮。

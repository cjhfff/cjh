# 11 第 4 轮开发清单：让 cjh「能干活」（2026-11-18）

## 背景

老大的反馈：内容上少了很多。核对结果：

- cjh 现在 67 个接口、14 张表；Alma 827 个接口、90 张表
- **最大的差距**：API 模型（sub2api 等）在 cjh 里**没有任何内置工具**，只有用户自己配的 MCP。没配 MCP 时就是一个纯聊天框，不能搜网页、读写文件、跑命令、管理定时任务。Alma 给模型带了一整套内置工具、44 个内置技能，以及一个能操作主程序的 CLI
- cjh 没有自带任何内容：不带技能，提示词库是空的，没有新手引导

本轮目标：**用 sub2api 的模型在 cjh 里也能像 Claude Agent 一样动手干活**，并接上飞书和记忆。

分工：hydrogen 实现 → argon 查漏（只出报告，不改代码）→ carbon 按报告补缺 → 小昌复验。

基线：git 提交 `222918e`。用 `git diff 222918e` 看本轮改动。

## R1 内置工具（最重要）

给所有非 ACP 的模型提供一套内置工具，和 MCP 工具合并后一起交给 AI SDK `streamText`。

| 工具 | 说明 | 是否需要确认 |
|---|---|---|
| `web_fetch` | 抓取 URL，HTML 转 Markdown，限制大小（如 200KB）、超时 20s；只允许 http/https | 否 |
| `web_search` | 搜索网页。设置里可选搜索后端：Tavily / Brave / SearXNG（填 key 或地址，key 加密存储）；都没配时用 DuckDuckGo HTML 页兜底 | 否 |
| `fs_list` / `fs_read` / `fs_glob` / `fs_grep` | 在线程绑定的工作目录内列目录、读文件（支持行范围）、按模式找文件、搜内容。路径必须在工作目录内（复用 B7 的越界检查） | 否 |
| `fs_write` / `fs_edit` | 写文件、按「旧文本 → 新文本」精确替换 | **是** |
| `shell_exec` | 在工作目录执行命令。Windows 用 PowerShell，参数数组、不走 shell 字符串拼接；超时（默认 120s）、输出截断（如 30KB） | **是** |
| `cron_list` / `cron_create` / `cron_delete` | 管理定时任务 | create/delete **是** |
| `usage_query` | 查询用量统计 | 否 |
| `skill_read` | 读取某个已启用技能的完整 `SKILL.md`（渐进加载：系统提示词里只放名称和描述） | 否 |
| `memory_save` / `memory_search` | 见 R4 | 否 |

要求：

1. **权限确认复用 ACP 那一套**：`permission_requested` / `permission_resolved` 事件、界面里同一个审批卡、同样的超时默认拒绝。选项：允许一次 / 本线程总是允许该工具 / 拒绝
2. 设置里有「只读工具自动允许」开关（默认开）；线程上可以单独关闭内置工具
3. 没绑定工作目录时，文件和命令类工具返回明确错误：「请先为该线程绑定工作目录」
4. 工具调用在界面上和 ACP 的工具卡片一样显示（标题、参数、输出、状态）
5. `stopWhen` 的步数上限放进设置（默认 20）
6. 执行跟踪（B9）记录每次内置工具调用

## R2 自带技能 + 新手引导

1. 随包带 `resources/skills/`，首批 5 个技能（内容自己写，不要拷贝 Alma 的）：
   - `cjh-self`：如何用内置工具和 `cjh` CLI 管理 cjh 自身（线程、定时任务、设置）
   - `web-research`：多源搜索、交叉验证、给出处
   - `daily-report`：生成日报的通用流程（收集 → 汇总 → 发送到线程或飞书）
   - `code-review`：在工作目录里审查改动（配合 git diff）
   - `file-organizer`：整理目录、批量重命名（先列计划再执行）
2. 技能来源分三类并在界面上区分：自带 / `~/.claude/skills` / cjh 数据目录 `skills/`
3. **首次启动引导**（可跳过，设置里能重新打开）：
   - 第 1 步：添加模型来源（sub2api 预设一键填好，只需填 key；或 Claude Agent 预设）
   - 第 2 步：选默认模型和工具模型
   - 第 3 步：是否启用 `~/.claude/skills` 里的技能（列出来逐个勾选）
   - 第 4 步：是否创建「每日 7:30 日报」定时任务
4. 提示词库预置 5 条常用提示词（总结、翻译、润色、解释代码、写提交信息）
5. 各页面的空状态给出下一步操作按钮

## R3 飞书桥接

1. 用飞书开放平台官方 SDK `@larksuiteoapi/node-sdk`，**长连接事件订阅**（WSClient），不需要公网回调地址
2. 设置页「渠道」：填 App ID、App Secret（加密存储），连接状态、最近事件、断开 / 重连
3. 表 `channel_mappings`：(platform, external_chat_id, external_user_id) → thread_id，私聊和群聊都支持（群聊只响应 @机器人）
4. 收到消息 → 走 WS `generate_response`（`source=feishu`）→ 生成结束把最终回复发回飞书；生成过程中先回一条「思考中…」，结束后更新为最终内容（消息更新或卡片）
5. 飞书侧命令：`/new` 新线程、`/stop` 停止、`/model <id>` 换模型、`/help`
6. **权限请求在飞书里也能审批**：发一张带「允许 / 拒绝」按钮的卡片，回调走 `permission_response`；超时默认拒绝
7. **定时任务可以投递到飞书**：cron 任务增加「投递到飞书会话」选项，生成结束后把回复发到指定会话
8. 渠道相关日志统一用 `[Bridge:feishu]` tag

## R4 记忆（简单版）

1. 存储：数据目录 `memory/`，一条一个 Markdown 文件（frontmatter：id、标题、标签、创建时间、来源线程），另建 FTS5 索引
2. 工具：`memory_save`（模型主动记）、`memory_search`
3. 每轮生成前按用户消息做 FTS 检索，取前 5 条注入系统提示词（设置里可关）
4. 界面：「记忆」页，列表、搜索、查看、编辑、删除、手动新增
5. `cjh memory add/search` CLI 命令

## R5 CLI 补齐

`cjh` 增加：`cron list/add/rm/run`、`search <q>`、`memory add/search`、`thread send <id> <text>`（等待生成结束后打印回复）。技能里的操作都能通过 CLI 完成。

## 通用要求

1. 每个功能前后端打通：后端 + 数据库迁移（老库能升级）+ 界面入口；界面沿用 `components/ui/primitives.tsx` 和 `styles.css` 的风格
2. 新文案全部用 i18n key
3. 不改动已有安全逻辑：线程级 ACP 会话隔离、子进程环境变量黑名单、权限模式 fail-closed、工作区越界检查
4. 新增单元测试至少覆盖：内置工具的越界拦截和需要确认的工具超时拒绝、`shell_exec` 超时和输出截断、`skill_read`、飞书消息到线程的映射（mock SDK）、记忆的保存和检索、cron 投递
5. 全部做完依次运行 `npm run typecheck`、`npm test`、`npm run build`，必须全部通过
6. 最后在本文件末尾追加「开发完成说明」：逐条写做了什么、改了哪些文件、哪些没做完（如实写）

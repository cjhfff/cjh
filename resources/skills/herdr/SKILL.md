# herdr 终端工作区委派指南 (`herdr`)

通过 `herdr_*` 内置工具，你可以把复杂的编码、重构、测试排查或长耗时命令委派给本地持久终端中的代理（如 `agy`、`codex`、`claude`、`pi`）或普通 `shell`，并持续跟进状态、处理交互阻塞与回收结果。

## 1. 什么时候委派给终端代理 vs 直接用内置工具

- **适合委派给 `herdr_run`（终端代理 / 后台终端）**：
  - 跨多个文件的代码实现、重构或架构改动；
  - 需要多轮「改代码 → 跑测试 → 修复报错」的闭环任务；
  - 长耗时构建、测试套件、服务启动（用 `shell_exec` 会一直阻塞当前轮次，而 `herdr_run` 可后台运行并随时观察/中断）。
- **直接用内置 `fs_*` / `shell_exec`**：
  - 单文件小改动、快速检索代码、几秒内完成的只读命令或直接回答用户的问题。

## 2. 如何选择 Agent 与编写自包含任务

- **先看现场**：开始委派前先调用 `herdr_list` 了解当前已有终端与工作目录，避免重复创建或误触用户正在使用的会话。
- **Agent 选择**：
  - `agy`：Antigravity 本地代理（适合通用工程改造与代码排查）；
  - `codex`：OpenAI Codex CLI（cjh 服务端已自动附加 `--no-daemon`，避免命令脱离终端上下文）；
  - `claude`：Claude Code CLI；
  - `pi`：pi 编码代理；
  - `shell`：纯命令行环境，配合 `line` 执行长耗时构建/测试脚本（如 `"npm test"`）。
- **任务提示词必须自包含、边界清晰**：
  - 明确 **`cwd`**（默认取当前线程绑定的 `workspacePath`，跨目录时显式指定）；
  - 明确**目标文件与范围**（只改哪些文件，禁止擅自修改无关模块）；
  - 明确**验收命令**（例如要求改完后运行指定单测或 `typecheck` 并回报结果）；
  - 明确**约束条件**：要求代理以交互模式运行，禁止私自再启动子代理（no subagents），禁止执行 `git push` 或破坏性操作；
  - **首条任务随 `herdr_run` 的 `task` 参数一并传入**：刚启动的代理可能仍在初始化，把首条指令放在 `task` 中由 herdr 统一等待就绪后投递，比先启动再立刻 `herdr_send` 更可靠。

## 3. 跟进模式：`follow: true` vs `herdr_wait`

- **异步自动跟进（推荐用于长任务）**：
  - 在 `herdr_run` 或 `herdr_send` 中传入 `follow: true`。
  - 同一终端同一时刻只能被**一个线程** follow。
  - 当该终端每次从 `working` 停下（进入 `done`、`idle`、`blocked`、`error` 或 `finished`）时，系统会自动读取其最新屏幕尾部并注入一条回调消息触发本线程继续决策。
  - 任务彻底结束后可调用 `herdr_unfollow` 取消跟进。
- **同步等待（适合短任务或等待特定输出）**：
  - 调用 `herdr_wait`（单次超时上限 300 秒；`output` 可匹配如服务启动成功的关键词）。
  - 等待返回后务必调用 `herdr_read` 读取实际屏幕输出核对结果，不要仅凭预期猜测成功。

## 4. 处理 `blocked` 状态（权限确认 / 提问 / 认证）

终端状态变为 `blocked`（`kind` 为 `permission`、`question` 或 `auth`）时，说明终端代理正在等待人工确认或选择：

1. **必须先调用 `herdr_read`（必要时增加 `lines`）查看完整屏幕上下文**，看清它要执行什么命令、修改什么文件或询问什么问题。
2. **严禁盲目使用 `herdr_send(..., { force: true })` 绕过权限决策**。
3. 若涉及敏感操作（执行高危命令、越界修改、删除文件、安装依赖、外部认证等），**必须先向用户汇报屏幕上的选项与风险，等用户明确同意后**，再调用 `herdr_answer`（传选项编号 `choice` 或文本 `text`，必要时设 `useArrows: true`）作答。
4. 若 `send` 因终端非空闲失败，先 `herdr_read` 确认状态，不要盲目重复发送。

## 5. 安全红线与清理规范

- **绝不干扰用户的终端**：用户机器上可能运行着他自己的 `agy` / `codex` / `claude` 会话。绝对不要对**非本线程/非本次任务创建**的终端执行 `herdr_send`、`herdr_keys`、`herdr_answer` 或 `herdr_kill`。
- **只清理自己启动的终端**：确认工作结果已验收并向用户汇报后，仅对自己创建的终端调用 `herdr_kill`（可传 `remove: true` 同时移除记录）与 `herdr_unfollow`。

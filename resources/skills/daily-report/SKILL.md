# 每日工作与运行日报生成流程 (`daily-report`)

用于每日定时汇报（如 07:30 日报）或用户主动要求汇总今日/昨日进展。

## 1. 信息收集
- 调用 `usage_query`（如 `days: 1` 或 `days: 7`）收集近期模型调用次数、主对话/杂活 Token 消耗与高频模型。
- 调用 `cron_list` 检查定时任务运行状态及是否存在失败记录 (`lastStatus === 'error'`)。
- 若当前线程绑定了本地工作目录，可用 `shell_exec`（如 `git log --since="24 hours ago" --oneline`）或 `fs_list` 查看近 24 小时代码与文档变更；也可调用 `memory_search` 回顾关键事项。

## 2. 汇总整理（精炼、可扫描）
按以下固定结构组织日报（控制在 1 分钟内可读完的篇幅）：
1. **核心进展 / 昨日摘要**：3～5 条要点（区分已完成与进行中）。
2. **模型与任务状态**：Token 消耗概况、定时任务执行是否全部正常；如有异常标出错误原因。
3. **今日建议 / 待办事项**：优先级最高的 1～3 项下一步动作。

## 3. 投递说明
- 在对话或定时任务中直接输出最终 Markdown 日报内容即可（若定时任务已配置飞书投递目标，系统会在生成完成后自动转发至飞书会话）。
- 避免堆砌原始 JSON 或冗长日志，只保留关键数字与结论。

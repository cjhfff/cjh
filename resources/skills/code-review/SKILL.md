# 工作区代码审查指南 (`code-review`)

当用户要求审查本地改动、PR 变更或某个模块质量时按此流程执行。

## 1. 获取上下文与变更范围
- 确认当前线程已绑定工作目录（未绑定时提醒用户绑定）。
- 使用 `shell_exec` 执行只读 Git 命令查看现状：
  - `git status --short`
  - `git diff`（未暂存改动）及 `git diff --cached`（已暂存改动）
  - 必要时用 `git log -n 5 --oneline` 了解近期上下文。
- 针对被修改的文件，用 `fs_read`（结合 `startLine`/`endLine`）阅读完整函数上下文，并用 `fs_grep` 检查相关调用方。

## 2. 审查维度（按严重度排序）
1. **正确性与边界条件**：空值处理、异步竞态、资源释放、分页/截断边界、Windows 路径差异。
2. **安全红线**：命令注入（是否走 `shell: false` 参数数组）、路径穿越、敏感密钥泄露、越权访问。
3. **性能与可靠性**：N+1 查询、大文件内存占用、超时与错误兜底。
4. **可维护性与一致性**：是否与仓库现有类型定义、i18n、错误处理模式保持一致。

## 3. 输出格式
- 先给出总体评价（可合并 / 建议修改后合并 / 存在阻塞问题）。
- 按 **严重度（高 / 中 / 低）** 列出问题，每条附带：**文件路径与行号**、**问题原因**、**具体修复建议**。
- 只基于实际读取到的文件与 diff 发言，不猜测未读代码。
